# Kavach spec (from the project brief, §2–§3). Used as the reference for independent review.

Kavach is a real-time scam-call protector for a hackathon. English only (language is a config value).
Ground rules that matter for review: secrets only in `.env`; the browser never sees the main API key; only the
user's own consented voice is cloned; the takeover persona never reveals real data and only uses clearly fake decoy
details; the complaint report is a DRAFT the user files themselves and nothing is ever auto-submitted; no real
outbound calls; "no fake success" — claims need evidence.

## Demo architecture (call simulator)
- FastAPI backend acts as the "phone line" relaying audio between two browser tabs: Caller (the scammer) and Receiver
  (the protected user).
- The backend taps each party's audio separately, so speaker identity comes from the channel (no diarization). The
  caller channel goes to scam detection; the receiver channel is used for barge-in and context.
- Warnings (F2) play only on the Receiver tab.
- Takeover (F3) mutes the receiver's mic toward the caller and injects persona TTS audio into the Caller tab's stream.
- The eval harness (F6) feeds pre-rendered TTS audio into the caller and receiver channels through the same backend
  path (same pipeline, so metrics are honest).

## F1 — Live listening and scam-stage detection
Stages (a call can hit several, in any order): S1 Authority impersonation (police, CBI, ED, customs, TRAI, RBI, bank,
courier, court); S2 Threat or fear (arrest, warrant, case filed, account freeze, illegal parcel, SIM block); S3
Isolation or secrecy (don't tell anyone, stay on the call, move to video call, don't disconnect); S4 Urgency (within 1
hour, immediately, or else); S5 Credential request (OTP, PIN, CVV, card number, Aadhaar, PAN, password); S6 Payment
request (UPI transfer, "safe or RBI verification account", gift cards, fees or fines); S7 Remote access (AnyDesk,
TeamViewer, screen share, installing an APK).
- Run detection on each finalized caller turn, plus a rolling window of the last ~6 turns.
- LLM returns strict JSON {stages, evidence_quotes, risk 0-100, rationale}; validate with Pydantic; retry once on bad JSON.
- Risk is cumulative with hysteresis: rises fast, decays slowly. Trigger the warning when risk >= threshold
  (configurable; tuned on the eval TRAIN split only) OR when S5, S6 or S7 appears together with any of S1–S3.
- Target: warning audio starts <= 3 s after the end of the triggering caller turn. Log every timing.
- Show live stage chips, the risk meter and the transcript on the Receiver and dashboard pages.

## F2 — Family-voice warning
- Use the cloned voice ID from `.env` (KAVACH_WARNING_VOICE_ID). Cloning is dashboard-only.
- Warning templates chosen by the main stage; 2–3 short sentences, plain English, full stops and "…" for calm pacing.
- Stream with the TTS-1 WebSocket session. If the receiver starts speaking (VAD or a partial transcript on the receiver
  channel) send Cancel immediately.
- Write numbers in words. Measure and log time-to-first-audio for every warning.

## F3 — Takeover persona
- Button on the Receiver tab "Hand over to Kavach". Afterwards receiver mic -> caller is muted and persona TTS -> caller
  is injected.
- Persona: slow, polite, slightly confused; keeps asking clarifying questions. NEVER real data; obvious decoys only,
  defined in config and flagged as fake in logs.
- Goal: keep the scammer talking and get them to state UPI ID, account/IFSC, name, badge/officer ID, callback number, links.
- Evidence extraction: an LLM pass on every caller turn returns JSON entities {type, value, quote, timestamp}; stored in
  SQLite; shown live in an evidence panel.
- "Take back" returns control instantly and cancels any persona TTS that is playing.
- Persona uses a library TTS voice different from the family voice.

## F4 — Family alert
- Telegram sendMessage to TELEGRAM_CHAT_ID when the warning triggers, again when takeover starts, and when the call ends
  (with a link or path to the report).
- Rate limit: at most 1 alert per stage change and at most 3 per call.
- Message contains risk score, stages, a <= 2-line transcript snippet and the time (IST).

## F5 — 1930 complaint draft
- Generated when the call ends. Fields: date/time (IST), caller number (from the simulator's metadata), claimed identity
  and agency, stages detected, amounts demanded, UPI IDs, accounts, IFSC, links, apps requested, timestamped key quotes,
  and whether money or OTP was shared (ask the user via UI checkboxes).
- Footer with next steps: call 1930, file at cybercrime.gov.in, report the number on Sanchar Saathi (Chakshu), contact
  your bank to freeze or dispute.
- Markdown and PDF, with a clear "DRAFT — review before filing" banner. Never auto-submits anything.

## F6 — Evaluation harness
- Dataset 60–100 English two-party scripts generated by an LLM: ~45 scam (digital arrest, bank KYC, courier/customs,
  investment/task, fake relative emergency, remote-access tech support), ~30 legit, ~15 hard negatives (legit calls that
  mention OTP or police safely). Each script JSON has label, scam type, decisive_turn_index (first turn where a careful
  human would be sure it is a scam; null for legit).
- Render each turn with TTS-1, different voices/accents for caller and receiver; save wav + timing JSON; respect rate
  limits by pacing and reusing sessions.
- Split 60% train (tune prompts/threshold) / 40% held-out test. Report TEST numbers only in the scoreboard and README.
- Metrics: recall on scams; false-positive rate on legit and hard negatives (separately); median and p90 seconds from
  the decisive turn to the warning; median warning time-to-first-audio; % of scams caught before the S5 or S6 request is
  completed.
- Scoreboard page: summary table, per-call table (click to play audio, see transcript and triggers), confusion matrix.
- README caveat: TTS audio is cleaner than real phone audio, so real-world numbers may be lower.
